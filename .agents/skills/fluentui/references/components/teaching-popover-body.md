# TeachingPopoverBody

> **Package**: `@fluentui/react-teaching-popover` v9.7.0
> **Import**: `import { TeachingPopoverBody } from '@fluentui/react-components';`
> **Category**: overlays
> **Stability**: stable

## Overview

TeachingPopoverBody is the content region of a TeachingPopover, the onboarding and feature-education overlay in Fluent UI React v9. It renders inside a TeachingPopoverSurface and holds the explanatory copy, imagery, and inline content that teaches a user about a feature before they dismiss or advance through the coaching flow. The body exposes two slots: a required root element that wraps and lays out the body content, and an optional media slot for illustrative content such as an image, illustration, or an embedded TeachingPopoverCarousel. Its single prop, mediaLength, controls how much vertical room the media area is allowed to occupy so the popover keeps a predictable footprint regardless of the intrinsic size of the illustration.

**When to use**: Use TeachingPopoverBody whenever you are authoring the interior of a TeachingPopover and need a consistent content container with an optional media region. Pair it with TeachingPopoverTitle for the headline, TeachingPopoverFooter for actions and dismissal, and TeachingPopoverCarousel when the lesson spans multiple steps. Prefer a plain Popover with PopoverSurface when you need a generic tooltip-like overlay with no coaching structure, and prefer Dialog when the user must make a decision or complete a task before continuing. TeachingPopoverBody is specifically for first-run experiences, feature announcements, and guided education where the content is informational and dismissible rather than blocking.

## Best Practices

### Do's

- Keep body copy short and scannable — one or two sentences that explain the value of the feature rather than documenting it.
- Use the media slot only when the illustration genuinely clarifies the message, and choose a mediaLength value that matches the illustration's aspect ratio.
- Pick mediaLength="short" for icon-scale or flat illustrations, "medium" for standard 16:9 imagery, and "tall" for portrait or instructional screenshots that need extra vertical space.
- Place every action, including the primary and dismiss buttons as well as the carousel navigation, in TeachingPopoverFooter or TeachingPopoverCarouselFooter so the body remains purely presentational.
- Keep the media consistent across every page of a TeachingPopoverCarousel — either render media on all carousel pages or on none of them — so the layout does not jump between steps.
- Provide the accessible name for the popover through TeachingPopoverTitle so screen readers announce what the body is discussing when focus enters the surface.
- Mark decorative imagery with aria-hidden and give meaningful imagery alternative text so assistive technology is not read a purely ornamental illustration.

### Don'ts

- Don't place the primary action inside the body root slot — actions belong in TeachingPopoverFooter where they get correct ordering and layout.
- Don't cram long paragraphs, tables, or scrollable regions into the body; teaching popovers should be digestible at a glance, and long content should move into a Dialog or a documentation page.
- Don't set mediaLength="tall" for a small decorative graphic, since the reserved space will leave a large empty gap and make the popover feel broken.
- Don't render media when the mediaLength expectation doesn't match — mismatched sizing either crops the illustration or produces dead whitespace.
- Don't nest another overlay such as a Popover, Menu, or Tooltip inside the body, because the already-layered popover surface makes the second overlay hard to position and dismiss.
- Don't rely on the body alone for accessibility context — omitting a TeachingPopoverTitle leaves the popover without an accessible name.
- Don't use the body as a data-entry form region; form fields belong in Dialog where focus management and validation semantics are stronger.
