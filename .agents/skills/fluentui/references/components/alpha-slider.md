# AlphaSlider

> **Import**: `import { AlphaSlider } from '@fluentui/react-components';`
> **Category**: forms
> **Stability**: stable

## Overview

AlphaSlider is a specialized slider control in the Fluent UI React v9 forms family that edits the alpha channel of a color, letting users make a color more opaque or more transparent. It renders a continuous, draggable track whose gradient visualizes the alpha ramp so the current position reads as a color value rather than an abstract number. AlphaSlider is designed to be composed with the other color inputs in the library — ColorPicker, ColorArea, ColorSlider, and ColorSwatch — so a user can build or refine a color, including its transparency, in a single panel. Its interpretation of the alpha channel is configurable through the transparency prop: when transparency is false the channel represents the opacity of the color, and when transparency is true it represents the transparency of the color, so a 30% transparent color corresponds to 70% opacity. Because alpha is invisible on its own, AlphaSlider is almost always used alongside a preview surface that composites the resulting color over a background.

**When to use**: Use AlphaSlider when a user needs to control the opacity or transparency of a color as a standalone, continuous value — for example in theme or design-token editors, brand color authoring tools, background and overlay color configuration, or anywhere a color must be blended with what is behind it. Reach for it together with ColorArea, ColorSlider, and ColorSwatch when you need a full color picker experience, and use ColorPicker when you want the complete picker surface assembled for you. Choose ColorSlider instead when the user is editing a hue, saturation, or lightness channel rather than alpha, and choose the general-purpose Slider when the value being edited is not a color channel at all. If transparency has no meaning in your scenario (for example an opaque-only palette), the slider should be omitted or disabled rather than shown as an inert control.

## Best Practices

### Do's

- Give every AlphaSlider a distinct accessible name — pair it with a Label or Field, or an explicit aria-label — so that screen reader users can tell the alpha control apart from the hue and saturation controls next to it.
- Set the transparency prop once, deliberately, and keep it identical across every alpha control in the same picker; the same numeric position means opposite things depending on this flag.
- Always show a live preview of the resulting color (for example a ColorSwatch or an ImageSwatch) because an alpha value alone gives the user no way to judge the outcome.
- Treat fully transparent as a legitimate, selectable end of the range, and make sure your color model round-trips it instead of dropping the RGB components.
- Keep AlphaSlider's enabled and disabled state synchronized with the rest of the color controls so the user never sees part of the picker live and part of it inert.
- Pair the slider with a text input or numeric readout when exact values matter, since fine-grained alpha adjustments are hard to hit by dragging alone.
- Provide a visible text representation of the current alpha next to the control so the value is not communicated by position and color alone.

### Don'ts

- Don't reuse AlphaSlider as a general numeric range control for non-color values; the gradient track and color semantics mislead users — use Slider instead.
- Don't change the transparency prop while a user is interacting with the picker, because the same thumb position suddenly represents the inverse of what it represented a moment ago.
- Don't ship a bare slider with no label or readout; the gradient communicates 'color' but not which channel or what value is selected.
- Don't use AlphaSlider to edit hue, saturation, or lightness — those channels belong to ColorSlider and ColorArea.
- Don't place several unlabeled sliders in one color panel; screen reader users will hear an indistinguishable series of 'slider' announcements.
- Don't assume that an alpha of zero means the color can be discarded; the underlying color channels still matter for interpolation and for when opacity is raised again.
