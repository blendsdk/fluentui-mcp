## Feature Overview

This requirement defines the deterministic foundation of the skill: the raw schema that the
scraper extracts from FluentUI React v9 source, and the guarantee that it covers every public v9
component with exact names, props, slots, default values, JSDoc descriptions, and real Storybook
examples. Nothing in this layer is generated by an LLM, so its output is reproducible from a pinned
source revision.

The layer exists because the skill's credibility rests on its API surface being correct. The
current scraper covers 62 components but misses the Button family (CompoundButton, MenuButton,
SplitButton, ToggleButton) and abbreviates some names (`Progress`, `Search`). Those gaps must be
closed before the skill is generated.

## Functional Requirements

### Must Have

- [ ] The scraper discovers every public component exported from `@fluentui/react-components` for
      the pinned v9 revision and records it with its exact display name (for example `ToggleButton`,
      `ProgressBar`, `SearchBox`, `DataGrid`).
- [ ] Each component records: `name`, `id` (kebab-case), `packageName`, `packageVersion`,
      `importPath`, `importStatement`, `category`, `stability`, `deprecated`, `deprecationMessage?`,
      `props[]`, `slots[]`, `stories[]`, `relatedComponents[]`, `additionalExports[]`.
- [ ] Each prop records `name`, `type`, `required`, `defaultValue?`, `description`, `deprecated`,
      `inherited`, `source`.
- [ ] Each slot records `name`, `elementType`, `alternativeTypes?`, `required`, `description`.
- [ ] Each story records `name`, `description`, `code` (complete, including imports and styles),
      `renderCode`, `sourceFile`, `imports[]`.
- [ ] Every component is classified into exactly one of the eight categories: `buttons`, `forms`,
      `navigation`, `data-display`, `feedback`, `overlays`, `layout`, `utilities`.
- [ ] The scraper source ref is pinned to the latest stable FluentUI release tag at generation time;
      `sources.fluentui.ref` records the tag and `sources.fluentui.commit` records the full commit.
- [ ] `sources.fluentui` also records the umbrella package's `packageName` and `packageVersion`
      (for example `@fluentui/react-components` 9.74.1) when the umbrella package is present, so
      the schema names the single suite version most readers recognize.
- [ ] Raw schema carries `schemaVersion`, `version`, `generatedAt`, `sources`, and `stats`.
- [ ] A coverage report lists every public v9 component and marks it scraped or explicitly excluded
      with a reason (internal, unstable, non-component export).

### Should Have

- [ ] Utility packages (hooks and helpers) are extracted with `exports[]`, parameters, and return
      types.
- [ ] `relatedComponents` is derived from package co-location (for example, the Button family).
- [ ] Deprecation notes are captured from `@deprecated` JSDoc tags.

### Won't Have (Out of Scope)

- v8, v10, Northstar, and non-React Fluent packages — AR-02.
- LLM-authored descriptions in this layer — Layer B, RD-02.
- Generated code examples — examples come only from scraped stories — AR-09.
- Runtime scraping or network calls in the skill — RD-07.

## Technical Requirements

### Source revision resolution

| Item | Rule |
|------|------|
| Default ref | Latest stable release tag of `microsoft/fluentui` |
| Override | `--fluentui-ref <tag>` CLI flag / `FLUENTUI_REF` env var |
| Recording | `sources.fluentui.ref`, `.commit`, `.repo`, `.scrapedAt` written into the raw schema; the umbrella package's `.packageName` and `.packageVersion` are recorded when that package is present |
| Contrib | `microsoft/fluentui-contrib` ref pinned the same way when included |

### Component identity rules

- Display name is the exported React component name (`ToggleButton`), not the package name.
- `id` is the lowercased kebab-case of the display name (`toggle-button`).
- A component is included only when it is a public React component; hooks, contexts, and pure
  types are recorded as `additionalExports` or utility entries, never as components.

### Coverage definition

"Complete" means: for the pinned revision, every symbol listed in the stable component entry point
of `@fluentui/react-components` is either represented as a component or recorded in the exclusion
report with a reason. The report is checked by a test so silent regressions cannot pass.

### Data model

```
Raw schema
├── schemaVersion: "1.0"        (bumped when the format changes — see RD-07)
├── version: "v9"
├── generatedAt
├── sources { fluentui {repo, ref, commit, scrapedAt, packageName?, packageVersion?}, contrib? }
├── components ─┬─ name, id, packageName, packageVersion, importPath
│               ├─ importStatement, category, stability, deprecated
│               ├─ props[], slots[], stories[]
│               └─ relatedComponents[], additionalExports[]
├── utilities[]
└── stats { totalComponents, totalUtilities, totalStories, totalProps, categoryCounts }
```

## Integration Points

### With RD-02 (LLM Enhancement)

Layer B consumes the raw schema produced here. Every prop, slot, and story an LLM prompt sees must
exist in this output; the API-reference gate in RD-04 re-checks that invariant.

### With RD-03 (Deterministic Skill Generator)

The generator renders component reference files from `props`, `slots`, and `stories`; it never
renders generated code from Layer B.

## Scope Decisions

| Decision | Options Considered | Chosen | Rationale | AR Ref |
|----------|-------------------|--------|-----------|--------|
| Version scope | v9 only / v8+v9+v10 / all | v9 only | Focus; the agent targets React v9 | AR-02 |
| Source ref | Latest stable tag / chosen version / master | Latest stable release tag | Reproducible with an explicit upgrade step | AR-20 |
| Component gaps | Fix now / defer / enhancer-only | Fix scraper discovery and classification now | The deterministic layer must be complete | AR-21 |
| Examples | LLM-authored / scraped stories | Scraped Storybook stories only | Real, compiled examples; no hallucination | AR-09 |
| Coverage proof | Manual review / automated report | Automated coverage report with a test | Prevents silent regressions | AR-21 |

## Security Considerations

> **🚨 Mandatory.** This layer reads third-party source and writes JSON; it handles no credentials
> and no user input.

- **Data sensitivity**: none; FluentUI source is public.
- **Input validation**: the scraper only reads files under the configured source directory; it must
  reject any resolved path that escapes that directory.
- **Authentication & authorization**: N/A — no server, no accounts.
- **Injection risks**: no shell execution; file paths are resolved and canonicalized before reads.
- **Encryption needs**: none at rest; any network clone uses HTTPS.
- **Rate limiting**: N/A — local static analysis.
- **Infrastructure**: N/A — no containers.

## Acceptance Criteria

1. [ ] For the pinned v9 revision, the coverage report accounts for every public component export
       of `@fluentui/react-components`; the set includes `CompoundButton`, `MenuButton`,
       `SplitButton`, `ToggleButton`, `ProgressBar`, `SearchBox`, and `DataGrid`, and no component
       uses an abbreviated name.
2. [ ] `data/v9/fluentui-schema.json` contains `sources.fluentui.ref` equal to the pinned release
       tag and a 40-character `sources.fluentui.commit`.
3. [ ] Every component entry has a non-empty `props` array; every story has non-empty `code`,
       `imports`, and `sourceFile`; and any component that is a re-export with no own props is
       listed in the coverage report with that reason.
4. [ ] Every component `category` is one of the eight allowed values; a test fails when any other
       value appears.
5. [ ] Running the scraper twice against the same checkout produces byte-identical JSON except for
       `generatedAt` and `scrapedAt`.
6. [ ] A test asserts the coverage report marks each known previously-missing component as
       scraped.
7. [ ] Security requirements verified: path-escape attempts in `--source` are rejected.
