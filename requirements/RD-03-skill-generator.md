## Feature Overview

This requirement defines how the enhanced schema becomes a distributable Agent Skill. A
deterministic generator reads the enhanced JSON and writes the skill's Markdown tree under
`.agents/skills/fluentui/`. No LLM runs at this stage; the same input always produces the same
bytes. The hand-written `SKILL.md` is never generated — only checked for existence — so routing
and hard rules remain human-owned.

Splitting generation from enhancement keeps the two concerns independently testable: content
correctness is Layer B's problem, presentation and routing are Layer C's.

## Functional Requirements

### Must Have

- [ ] `SKILL.md` exists at the skill root with YAML frontmatter containing `name: fluentui`, a
      `description`, `license`, and optional `compatibility`/`metadata`; its body is at most 500
      lines.
- [ ] The generator writes these reference files:
      - `references/index.md` — routing map (task families, categories, all references).
      - `references/foundation/<id>.md` — 6 foundation guides.
      - `references/components/<id>.md` — one file per component in the raw schema.
      - `references/categories/<category>.md` — 8 category guidance documents, each also listing
        its components with links.
      - `references/recipes/<group>/<id>.md` — one file per recipe.
      - `references/quick-reference/<id>.md` — 5 quick-reference documents.
- [ ] Each generated component file contains: identity header (name, package, import, category,
      stability, deprecation), overview prose, props table, slots table, examples rendered from
      **scraped stories**, and links to related recipes/categories.
- [ ] Component examples are drawn only from `stories[].code`; a component with no stories renders
      no Examples section.
- [ ] Generation is deterministic: sorted ordering, LF line endings, no timestamps, an explicit
      source→destination mapping, and all content prepared in memory before any write.
- [ ] Every generated file ends with the generated marker comment; hand-written files (SKILL.md,
      `assets/templates/*`) never receive it and are never overwritten by the generator.
- [ ] A manifest (`.fluentui-skill-manifest.json`) records the input schema hash, the generator
      version, and each generated file's hash.
- [ ] The generator refuses to run if the enhanced schema is absent, malformed, or fails schema
      validation, and writes no partial tree on error.

### Should Have

- [ ] `assets/templates/` contains at least: minimal app, form, dashboard shell, and admin CRUD.
- [ ] `references/index.md` includes a task-to-reference routing table and a category index.
- [ ] A `--check` mode regenerates to a temporary directory and reports differences without
      touching the committed tree (used by RD-04's drift gate).

### Won't Have (Out of Scope)

- LLM calls during generation — AR-05.
- VitePress or any rendered website — AR-16.
- Editing or wrapping the legacy `docs/` corpus — AR-04.
- Multi-version output trees — AR-02.

## Technical Requirements

### Skill tree

```
.agents/skills/fluentui/
├── SKILL.md                         # hand-written
├── assets/templates/*.md            # hand-written
└── references/                      # generated
    ├── index.md
    ├── foundation/<id>.md
    ├── components/<id>.md
    ├── categories/<category>.md
    ├── recipes/<group>/<id>.md
    └── quick-reference/<id>.md
```

### Determinism contract

| Rule | Detail |
|------|--------|
| Ordering | Components, recipes, and guides sorted by id/group then id |
| Encoding | UTF-8, LF only; `\r\n` normalized on read |
| Timestamps | None written into generated files |
| Atomicity | Build in memory; write only after all sources validate |
| Marker | `<!-- Generated by scripts/skill/generate.ts — do not edit by hand. -->` |
| Mapping | Explicit source→destination table in `scripts/skill/mapping.ts` |

### Rendering rules

- Props table columns: name, type, default, required, description (escaped pipe characters).
- Slots table columns: name, element type, required, description.
- Examples: render at most three stories per component, preferring the default and appearance
  stories; include the full story `code` in a `tsx` fence.
- Prose sections render only when their field is present (additive rendering).
- All internal links are relative and must resolve within the tree.

## Integration Points

### With RD-01 / RD-02

The generator treats the enhanced schema as immutable input and never mutates it.

### With RD-04

The drift and coverage gates call the same generator in `--check` mode, so generation and
verification share one implementation.

### With RD-05

The `assemble` step copies `.agents/skills/fluentui/` to `skills/fluentui/` for packaging.

## Scope Decisions

| Decision | Options Considered | Chosen | Rationale | AR Ref |
|----------|-------------------|--------|-----------|--------|
| Producer | Generator / enhancer | Deterministic generator from JSON | Diffable, gate-able, single responsibility | AR-05 |
| Granularity | Per component/topic / per category | Per component and per topic | Load only what a task needs | AR-06 |
| SKILL.md | Generated / hand-written | Hand-written, existence-checked | Routing and hard rules are curated | AR-05 |
| Completeness | Full offline corpus / lean | Full offline corpus | Works without `node_modules` or network | AR-11 |
| Name | `fluentui` / `fluentui-v9` | `fluentui` | Directory/name match required by the format | AR-02 |

## Security Considerations

> **🚨 Mandatory.** The generator writes filesystem paths derived from schema ids.

- **Data sensitivity**: none; all input is generated content.
- **Input validation**: every id is validated against a safe pattern before use as a path
  component; any `..`, `/`, or absolute value is rejected.
- **Authentication & authorization**: N/A.
- **Injection risks**: rendered values are markdown-escaped where a value could inject a heading,
  link, or table break; no shell is invoked.
- **Encryption needs**: none.
- **Rate limiting**: N/A.
- **Infrastructure**: N/A.

## Acceptance Criteria

1. [ ] Running the generator twice on the same enhanced schema produces byte-identical output for
       all generated files.
2. [ ] The generated tree contains exactly the files in the mapping: 6 foundation, N component
       files equal to the component count, 8 category files, one file per recipe, 5
       quick-reference files, and `index.md`.
3. [ ] Each generated component file ends with the generated marker; `SKILL.md` and
       `assets/templates/*` do not.
4. [ ] Component example sections contain only story code; a component with an empty `stories`
       array has no Examples heading.
5. [ ] `SKILL.md` frontmatter `name` equals the directory name `fluentui` and the body is ≤ 500
       lines.
6. [ ] Given a malformed schema, generation exits non-zero and no file under
       `.agents/skills/fluentui/` is created or modified.
7. [ ] A schema id containing `../` is rejected before any write.
8. [ ] Security requirements verified: generated content contains no secret-like material.
